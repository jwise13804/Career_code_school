# Career Code School

A free, friendly, interactive course that takes one adult learner from **customer support at a card/fintech company** to **junior backend developer** in about 12 months (6–8 hours a week). Lessons are 10–15 minutes, mobile-first and resumable, and every explanation draws on what she already knows about cards, payments and disputes.

It's a static site for **GitHub Pages**: no backend, no accounts, nothing leaves the browser.

- **Real code in the browser:** Python (Pyodide, in a Web Worker with a Stop button and a 10-second timeout) and SQL (sql.js) over a sample card-transactions database.
- **Honest simulations**, all clearly labelled: a Mini Bank API with a Postman-style request builder, a request-handler lab where her Python is the server, an idempotency lab, a Git/Docker/pytest terminal, a CI pipeline where failing tests block the deploy, and a dispute state-machine builder.
- **Quizzes** (multiple choice, fill in the blank, drag to order, match, spot the bug), with spaced review of missed questions.
- **Progress** saved in localStorage, with Export/Import to move between devices, a progress map from *Support* to *Developer*, and a streak that never shames missed days.
- A **"Stuck? Ask Claude"** button on every lesson, a searchable **glossary**, and a **zip download** of her capstone project plus all the code she's written.

## Curriculum

| Phase | Months | Content |
| --- | --- | --- |
| 1. Foundations | 1–3 | **16 complete lessons**: Python basics, mini project, SQL (SELECT → GROUP BY), Git & GitHub |
| 2. APIs, databases and tests | 4–6 | 12 lessons: 3 complete (what an API is, writing a handler, pytest), 9 outlines |
| 3. Shipping code | 7–9 | 9 lessons: 2 complete (Docker, GitHub Actions CI), 7 outlines |
| 4. Capstone | 10–12 | 11 lessons: 7 complete (tap to settlement, PCI DSS, PSD2/SCA, idempotency, disputes, portfolio, job applications), 4 outlines |

"Outline" lessons have a real summary, goals, a support-desk comparison and links to specific free resources, so she can study them now. They're marked `status: planned` and get full interactive content later.

The capstone starter in `content/project/` is a working FastAPI payments API (idempotency keys, double-entry ledger, dispute state machine, 17 pytest tests, Dockerfile, CI workflow, README template).

## Why this stack: plain ES modules, no build step

The site is plain HTML, CSS and JavaScript modules. **There is no build step.** GitHub Pages serves the repository files as they are.

- Nothing to install to edit content: add a Markdown file, push, done.
- Nothing to break: no bundler config, no lockfile churn, no "it built on my machine".
- Third-party libraries are **vendored** into `assets/vendor/` (CodeMirror 6 bundled once with esbuild, plus sql.js, marked and JSZip), so the site doesn't depend on extra CDNs. Pyodide (about 8 MB) is the one exception: it loads from jsDelivr, pinned to a version, and only the first time Python is needed.
- `npm install` is only needed to run the tests or to upgrade a vendored library (`npm run vendor`).

Vite would have worked too, but it adds a build step and a second way for deploys to fail, for no benefit to a content-driven site.

### Sub-path safe

Project sites live at `https://USER.github.io/REPO/`. Everything uses **relative URLs** (`content/…`, `new URL(…, import.meta.url)`) and **hash routes** (`#/lesson/p1-01-hello`), so the same files work at `/`, at `/REPO/`, or locally. The test server (`tools/serve.mjs`) only serves `/career_code_school/` and returns 404 elsewhere, so any absolute-path mistake fails the tests.

## Adding a lesson

1. Create `content/lessons/<id>.md`, e.g. `p2-02-status-codes.md`:

   ````markdown
   ---
   title: Methods and status codes
   minutes: 14
   summary: One sentence shown under the title.
   goals:
     - First thing she'll be able to do
     - Second thing
   ---

   ## A heading

   Plain Markdown. Link glossary terms like [[status-code]] or [[api|an API]].

   ```analogy
   A comparison from the support desk.
   ```
   ````

2. Add it to `content/course.json`, in the unit where it belongs. The `title` must match the front matter:

   ```json
   { "id": "p2-02-status-codes", "title": "Methods and status codes", "minutes": 14 }
   ```

   Add `"status": "planned"` (here and in the front matter) for an outline lesson.

3. Run `npm run check`. It catches missing files, mismatched titles, broken glossary links, bad JSON, failing lab solutions and broken SQL answers.

### Interactive blocks

Interactive pieces are fenced blocks whose language is a block type:

| Block | Format | What it is |
| --- | --- | --- |
| ```` ```lab ```` | sections | Python code lab with hidden checks, hints and solution |
| ```` ```quiz ```` | quiz id | Loads `content/quizzes/<id>.json` |
| ```` ```sql-lab ```` | JSON | SQL playground, optionally with challenges |
| ```` ```api ```` | JSON | Mini Bank API request builder, with optional tasks |
| ```` ```handler ```` | sections | Her Python `handle(method, path, body)` acts as the API |
| ```` ```terminal ```` | scenario id | Loads `content/terminal/<id>.json` |
| ```` ```idempotency ```` / ```` ```ci ```` / ```` ```dispute ```` | sections | The simulations |
| ```` ```video ```` | JSON | Video or "Watch" card (see TODO.md) |
| ```` ```download ```` | JSON | Zip download of `content/project/` files plus her saved code |
| ```` ```analogy ```` ```` ```tip ```` ```` ```note ```` ```` ```warning ```` ```` ```practice ```` | Markdown | Callout boxes |

Use ordinary ```` ```python ````, ```` ```sql ````, ```` ```text ```` fences for code that's only shown.

**A code lab** ("sections" format: `key: value` lines, then `--- name` sections; `hint` can repeat):

````markdown
```lab
id: p1-06-functions
title: Write two helper functions
--- task
Markdown instructions.
--- starter
def card_fee(amount):
    pass
--- tests
check("card_fee(100)", 1.5, tip="1.5% as a decimal is 0.015.")
check_output("Hello, Sam!")
--- hint
First nudge.
--- hint
Second nudge.
--- hint
Nearly the answer.
--- solution
def card_fee(amount):
    return max(round(amount * 0.015, 2), 0.20)
```
````

Check helpers available in `tests` (defined in `assets/js/workers/python-worker.js`):

- `check("expression", expected, tip=None, label=None)` evaluates the expression against her code and compares it with `expected`. On failure she sees e.g. *format_pounds(1250) gave 12.5, we expected "£12.50". We expected text (a string) but got a number.*
- `check_output("text", tip=None, exact=False)`: printed output contains this text.
- `check_no_output("text", tip=None)`: printed output must not contain this text.
- `check_true("expression", fail_message, pass_message=None, tip=None)`.
- `check_defined("name")`, and `record(ok, message, tip)` for custom checks.

`tools/verify-labs.py` runs every lab's solution (it must pass) and starter (it must fail at least one check) using this exact harness.

**An SQL lab:** challenges are compared by result rows (column values, not names). Set `"ordered": true` when the order matters.

```json
{ "id": "p1-12-sql", "title": "Filter and sort", "challenges": [
  { "id": "blocked", "prompt": "Show every blocked card.", "solution": "SELECT * FROM cards WHERE status = 'blocked';", "hint": "..." }
] }
```

## Adding a quiz question

Open the lesson's quiz file in `content/quizzes/` and add an object to `questions`. Every question needs a unique `id` within its quiz (spaced review stores answers by `quizId/questionId`, so **don't reuse or renumber ids**), a `prompt` (Markdown) and an `explanation` shown after answering.

```json
{ "id": "q7", "type": "mcq", "prompt": "Which code means *created*?",
  "options": ["201", "200", "404"], "answer": 0,
  "why": [null, "200 is plain success.", "404 is not found."],
  "explanation": "201 Created: something new exists now." }
```

| `type` | Extra fields |
| --- | --- |
| `mcq` | `options`, `answer` (index), optional `why` (one note per option) |
| `fill` | `answer` (string or list of accepted answers), optional `code`, `caseSensitive` |
| `order` | `items` in the **correct** order (they're shuffled for her) |
| `match` | `pairs`: `[["term", "meaning"], …]` |
| `bug` | `code`, `answer` (the buggy line number, starting at 1) |

## Glossary terms

Add to `content/glossary.json`: `slug`, `term`, `short` (plain definition), `everyday` (support-desk comparison), and optionally `aka` (extra search words) and `lesson`. Link from any lesson with `[[slug]]` or `[[slug|custom text]]`.

## Running locally

```bash
npm install
npm run serve        # http://localhost:4173/career_code_school/
npm run check        # content + lab + SQL checks (needs python3)
npm test             # Playwright, desktop + phone (Pyodide served offline from node_modules)
```

## Deployment

`.github/workflows/pages.yml` runs on every push to `main`. It runs the content check and lab verifier, copies the published files (`index.html`, `404.html`, `favicon.svg`, `.nojekyll`, `assets/`, `content/`) into `_site/`, and deploys them with `actions/deploy-pages`.

**One-time setup:** in the GitHub repository go to **Settings → Pages → Build and deployment → Source** and choose **GitHub Actions**. Until then the deploy job fails with "Get Pages site failed".

`.github/workflows/test.yml` runs the Playwright suite (desktop + phone viewports) against the real Pyodide CDN.

## Privacy

There are no accounts, analytics or cookies. Progress lives in this browser's localStorage under `ccs-progress-v1`; Export downloads it as a JSON file, and Import reads it back. Nothing is sent anywhere. The only network requests are for the site's own files, Pyodide from jsDelivr (when Python first runs), and YouTube only if she presses play on a verified video card.

## Known limitations

- **Python needs a connection the first time** (about 8 MB from jsDelivr); after that the browser cache usually serves it. SQL and everything else are bundled.
- **Stop** works by restarting the Python worker, so the next run reloads Python (fast from cache). True interrupts need cross-origin isolation headers, which GitHub Pages can't set.
- **`input()` isn't supported** in labs. Labs set values directly instead.
- **Simulations are simulations.** The terminal accepts the commands each scenario expects (with common variants and helpful mistake messages), not arbitrary shell commands. The Mini Bank API resets on reload. FastAPI, Docker, cloud and CI are taught with simulations and links to the real tools; the CI pipeline's lint and test stages do run her real Python.
- **Handler lab requests don't share state:** each request re-runs her code (explained in the lesson as the reason databases exist).
- **Progress is per browser.** Clearing site data deletes it, so the Progress page encourages exporting. Private browsing may block storage; the site keeps working and warns her.
- **Video embeds:** no YouTube IDs could be verified from the build environment, so every video is a "Watch" card linking to the official course page. See `TODO.md`.
- 20 of the 48 lessons are outlines for now (see Curriculum).
